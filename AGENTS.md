## Critical Reminders

- **Buffer phases (1.5, 2.5, 4.5, 8.5, 13.5, 19.5) are non-negotiable — they are the difference between "plan" and "delivered"**
- **Staffing: 7-10 developers minimum.** 2-3 C++ engine engineers, 2-3 Go services engineers, 1 DevOps/SRE, 1-2 QA/Validation. Dedicated Compliance officer required by Phase 21.
- **C++ core runs on bare metal** (no containers in hot path); Go services containerized in Kubernetes.
- **PostgreSQL `SERIALIZABLE` isolation** for all balance mutations and trade settlement — never `READ COMMITTED` for financial operations.
- **Aeron or shared-memory IPC** between C++ core and Go gateway — never HTTP/gRPC in the hot path.
- **Custom binary WAL** (mmap + fsync) — not Redis Streams, not PostgreSQL WAL for the order book.
- **ClickHouse for tick history** — not PostgreSQL (100x slower for time-series analytics).
- **Redis for sessions/cache only** — never the order book, never the WAL.
- **FIX protocol is FX-specific** (NoPartyIDs, SettlementType, FX-specific tags) — not equities FIX.
- **T+1/T+2 settlement** — forex standard, not instant crypto settlement.
- **Banking rails (SWIFT/SEPA/FedNow/ACH/CHAPS/TARGET2)** for deposits/withdrawals — no blockchain, no crypto custody.
- **No cryptocurrency** — fiat currencies only (USD, EUR, GBP, JPY, AUD, CAD, CHF, etc.).
- All 9 financial correctness specification acceptance categories mandatory (supersedes prior 8 categories — GL zero-sum balance sheet invariant added)
- Blue-green deployment with rollback script (Phase 9)
- Runbooks for every alert type (47+ documented in Phase 13.5)
- **Feature-completeness audit + internal-consistency pass are REQUIRED** before Phase 1 begins: all spec gaps must be task-backed in the phase docs and all cross-file values reconciled (see spec §27 for the decision log).
- **Always update meta-docs whenever the need arises:** Whenever architecture, workflows, routes, tasks, or canonical values are touched, immediately update the full meta-doc suite (`AGENTS.md`, `CLAUDE.md`, `CONTEXT.md`, `ARCHITECTURE.md`, `DESIGN.md`, `WORKFLOWS.md`, `MEMORY.md`) to maintain complete system-wide consistency.
